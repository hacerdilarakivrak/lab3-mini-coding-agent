
# Lab 3: A Mini Coding Agent

## Project Overview

This project implements a mini coding agent using Python, Ollama, and the `llama3.1:8b` language model.

The agent can inspect project files, read file contents, and run Python unit tests with explicit user approval.

The project demonstrates the main components of a coding agent: an iterative agent loop, structured tool calling, input validation, workspace context, safety checks, and a maximum step limit.

## Implemented Tools

The agent provides three tools:

- **list_files:** Lists files within the project directory.
- **read_file:** Reads the contents of a specified text file inside the project directory.
- **run_tests:** Runs Python unit tests after requesting explicit user approval.

Each tool includes a description and parameter schema to help the language model select and use it correctly.

## Agent Loop

The agent sends the user's request, system instructions, and available tool definitions to the Ollama model.

When the model requests a tool, the program validates the request, executes the appropriate tool, and returns the result to the model.

The process repeats until the model provides a final response or the maximum limit of 20 iterations is reached.

## Safety Features

- Only recognized tools can be executed.
- Missing, invalid, or unexpected tool arguments are rejected.
- File access is restricted to the project directory.
- Test execution requires explicit user approval.
- The test command is predefined rather than generated by the model.
- Test execution has a 30-second timeout.
- The agent does not provide file modification tools.
- The agent loop is limited to 20 iterations.

## Project Context

Before the agent loop starts, the program collects the project file structure and includes it in the system message.

This gives the model information about the workspace and helps it select relevant files and tools.

## Requirements

- Python 3.10 or later
- Ollama
- Ollama model `llama3.1:8b`
- Python dependencies listed in `requirements.txt`

## Installation and Usage

### 1. Install Dependencies

```bash
python -m pip install -r requirements.txt
```

### 2. Prepare the Ollama Model

Make sure Ollama is installed and running.

If the model is not installed, download it using:

```bash
ollama pull llama3.1:8b
```

### 3. Run the Agent

```bash
python mini_coding_agent.py
```

Enter a request when prompted. The agent can inspect files and request permission before running tests.

### 4. Run Automated Tests

```bash
python -m unittest discover -v
```

## Testing and Results

### Manual Agent Testing

**File inspection:** The agent successfully listed project files, read `README.md`, and summarized the project.

**Permission denied:** When the user entered `no`, the program correctly refused to execute tests. The language model initially misinterpreted this result and described the tool as unavailable.

**Initial test execution:** Before unit tests were added, the agent reported that no tests were found.

**Agent-executed tests:** With user approval, the agent successfully executed the initial four unit tests.

### Automated Unit Tests

The test suite was subsequently expanded to 12 tests covering:

1. Listing project files.
2. Reading project files.
3. Blocking access outside the project directory.
4. Requiring user approval for test execution.
5. Rejecting unknown tool names.
6. Rejecting invalid argument types.
7. Rejecting missing required arguments.
8. Rejecting unexpected arguments.
9. Rejecting unexpected arguments for `run_tests`.
10. Blocking unsafe paths through the tool dispatcher.
11. Verifying the configured maximum step count of 20.
12. Verifying that the agent loop actually stops after 20 iterations.

The latest test run produced:

```text
Ran 12 tests in 0.012s

OK
```

**Result: 12 out of 12 automated tests passed.**

The test suite verifies both the configured maximum step count and the agent's actual stopping behavior.

The new iteration-limit test uses a mocked model that repeatedly requests a tool. The test confirms that the agent stops after exactly 20 iterations rather than continuing indefinitely.

This test does not require a running Ollama server because the model responses are simulated.
