# Lab 3: A Mini Coding Agent

## Project Overview

This project implements a mini coding agent using Python, the OpenAI Python client, Ollama, and the `llama3.1:8b` language model.

The agent can inspect project files, read file contents, and run Python unit tests after receiving explicit user approval.

The project demonstrates the main components of a coding agent: an iterative agent loop, structured tool calling, input validation, workspace context, safety checks, and a maximum iteration limit.

To satisfy the OpenAI-compatible API requirement, the agent communicates with a locally running Ollama server through its OpenAI-compatible Chat Completions API. This approach allows the project to use a local language model without requiring a paid OpenAI API service.

## Implemented Tools

The agent provides three tools:

- **list_files:** Lists files within the project directory while excluding selected temporary and environment directories.
- **read_file:** Reads the contents of a specified text file inside the project directory.
- **run_tests:** Executes Python unit tests using `unittest` after requesting explicit user approval.

Each tool includes a name, description, and parameter schema to help the language model select the correct operation and provide valid arguments.

The tools are registered using the function-calling format supported by the OpenAI-compatible API.

## Agent Loop

The agent uses the OpenAI Python client to communicate with a locally running Ollama server through the OpenAI-compatible API endpoint:

`http://localhost:11434/v1`

The selected language model is `llama3.1:8b`.

When the agent starts, it sends the user's request, system instructions, and available tool definitions to the model.

If the model requests a tool, the program parses its JSON arguments, validates the tool name and parameters, and executes the appropriate Python function.

The tool result is added to the conversation history using the corresponding tool call ID. The updated conversation is then sent back to the model.

This process continues until the model generates a final response or the maximum limit of 20 iterations is reached.

The model temperature is set to 0.0 to encourage more consistent responses.

## Safety Features

The agent implements several safety controls:

- Only the three predefined tools can be executed.
- Missing, invalid, or unexpected tool arguments are rejected.
- File access is restricted to the project directory.
- Test execution requires explicit user approval.
- The test command is predefined rather than generated by the language model.
- Test execution has a 30-second timeout.
- The agent does not provide direct file modification tools.
- The agent loop is limited to 20 iterations.

These restrictions are enforced by the Python program rather than relying only on language model instructions.

Although the agent does not provide direct file modification tools, running Python tests can execute code with side effects. Therefore, user approval is required before test execution.

## Project Context

Before starting the agent loop, the program collects the project file structure using `list_files`.

The file structure is included in the system message to provide the model with information about the workspace.

The system message also instructs the model to use the available tools, avoid inventing file contents or test results, and recognize that direct file modification is not supported.

## Requirements

The project requires:

- Python 3.10 or later.
- Ollama installed and running locally.
- The Ollama model `llama3.1:8b`.
- The OpenAI Python package specified in `requirements.txt`.

The Python dependency is:

`openai>=1.0.0,<3.0.0`

## Installation and Usage

### 1. Install Dependencies

Open a terminal in the project directory and run:

`python -m pip install -r requirements.txt`

### 2. Prepare the Ollama Model

Make sure Ollama is installed and running.

If the model is not already installed, download it using:

`ollama pull llama3.1:8b`

To verify that the model is available, run:

`ollama list`

The model list should include `llama3.1:8b`.

### 3. Run the Agent

Start the agent using:

`python mini_coding_agent.py`

When prompted, enter a request describing what the agent should do.

For example:

`List the project files, read README.md, and briefly summarize the project.`

The agent will use the available tools to inspect the project and generate a response.

If the agent needs to run tests, it will request explicit user approval before executing the test command.

### 4. Run Automated Tests

Run the automated unit tests using:

`python -m unittest discover -v`

The tests use Python's built-in `unittest` framework.

The tests that simulate model responses do not require an active Ollama server.

### Earlier Testing Observations

During testing of the original implementation, the agent correctly refused to execute tests when the user denied permission.

However, the language model initially misinterpreted the denial and described the tool as unavailable. This demonstrated that the language model's explanation may differ from the actual tool execution result.

Before the automated test suite was expanded, the original agent also successfully executed four unit tests with user approval.

These observations refer to the earlier implementation that used the native Ollama Python client.

## Comparison with the Reference Agent

I compared this project with [rasbt/mini-coding-agent](https://github.com/rasbt/mini-coding-agent).

Both projects use Python and language models to implement iterative coding agents.

Both include tool handling, workspace context, safety checks, and execution limits.

My implementation is intentionally smaller and focuses on three tools: `list_files`, `read_file`, and `run_tests`.

It uses the `llama3.1:8b` model through Ollama's OpenAI-compatible API and has a fixed maximum limit of 20 iterations.

The reference project provides additional capabilities, including persistent memory, session recovery, context management, configurable approval modes, file modification tools, and bounded delegation to subagents.

Another difference is the model interaction format. My implementation uses structured function calls through the OpenAI-compatible Chat Completions API, while the reference project documents a prompt-based format using `<tool>` and `<final>` tags.

A more detailed comparison is available in [writeup.md](https://github.com/hacerdilarakivrak/lab3-mini-coding-agent/blob/main/writeup.md).
